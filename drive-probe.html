What does one Picker session with drive.file actually buy?

Throwaway probe. It requests only drive.file — a non-sensitive scope, so no verification and no unverified-app warning — opens the Google Picker, and then asks Drive what that pick actually bought — including whether it survives a reload. Nothing is written, nothing is stored, and no file leaves this page.

Before you run it

  1. In the Cloud project, enable Google Drive API and Google Picker API.
  2. Create an API key (APIs & Services → Credentials). Restrict it to this site's referrer if you like. This is the Picker's "developer key" — it is not a secret in the password sense, but don't commit it.
  3. Paste it below, grant access, then run test A, then C. B only if you have a folder with files in it.

Test D — the real corpus, and how many IDs the picker swallows

This page is on the same origin as the app, so it can read your actual knowledge base out of IndexedDB and harvest every Drive attachment it references. Scan first — it touches nothing and tells you how big the job is. Then open the picker pre-navigated to a batch of exactly those files (DocsView.setFileIds) and see whether it renders at that size.

For each batch: does the dialog open, does it list files, and what does it return when you select some and hit Select? A batch that opens to an empty or broken dialog is the limit.

Test A — control: pick a single file

Proves the plumbing works at all. If this fails, nothing about folders is meaningful yet.

Test C — the one that matters: a batch from Shared with me

Classroom attachments that a teacher posted as "students can view" are owned by the teacher and live under Shared with me — not in your Classroom/ folders, which is why those look empty. So the real question is whether you can hand over a whole batch at once. Open the picker, switch to Shared with me, and select as many files as you can (click one, then shift-click further down the list). The probe then checks how many of them it can actually read back.

Test B — folder cascade (only if you have a folder with files in it)

Your Classroom/<class> folders are usually empty, and an empty folder cannot answer this — so make a throwaway folder in your Drive, drop two or three files into it, and pick that. The probe then tries to read the folder, list its children, and download one child's bytes.
